# M7 · 恶意防刷（方案待定，先记录）

> 状态：**问题记录，方案未定**；先把场景和可选做法记下来，等要上线前再拍板
> 关联：M3 问卷、M4 审核台、M5 数据与合规

## 1. 要防什么

| 场景 | 具体表现 | 后果 |
| --- | --- | --- |
| 刷好评 | 某公司短期内涌入大量 4–5 星、内容雷同 | 等级虚高，平台失去参考价值 |
| 刷差评 | 竞品/前员工组织化刷 1 星 | 公司被误伤，法律风险 |
| 灌垃圾 | 脚本提交广告、链接、乱码 | 审核台被淹没，人工成本飙升 |
| 探测接口 | 脚本反复提交找规律、试字段 | 暴露规则、消耗资源 |
| 分布式低频 | 多个网络、每次只提交几条 | 单 IP 限流失效 |
| 内容农场 | 用模板批量生成“像真的”评价 | 相似度低，难自动识别 |

> 平台不要求登录，天然对脚本友好；这是匿名换来的代价，只能靠“入口门槛 + 异常识别 + 人工审核”三层来补。

## 2. 现在有什么（已实现的部分）

| 机制 | 现状 | 效果 |
| --- | --- | --- |
| 频率限制 | 同一网络每分钟最多 5 次、每天最多 100 次 | 挡住单点高频 |
| 内容去重 | 24 小时内相同“公司+项目+正文”视为重复 | 挡住复制粘贴 |
| 隐藏诱饵字段 | 正常用户看不到，脚本容易填 | 挡住低级脚本 |
| 填写耗时 | 少于 3 秒提交会被标记 | 挡住“瞬间提交” |
| 提交前计算挑战 | 需要算一道小题目才能提交 | 抬高成本，但目前是“自证”，可绕过 |
| 人工审核 | 每条都过人工 | 最后一道闸，但量大时会被拖垮 |

## 3. 原则（先定边界，再谈方案）

1. **不误伤真实用户**：正常用户不应看到验证码之外的额外步骤
2. **不破坏匿名**：不引入账号、手机号、邮箱验证，不做设备指纹
3. **规则可解释**：被拦时告诉用户“提交太频繁，请稍后再试”，而不是静默失败
4. **成本可控**：优先用现成能力，不为了防刷自建复杂系统
5. **不公示细节**：不对外公布具体阈值，避免被针对性绕过

## 4. 可选机制（方案池，未定）

| 机制 | 做法（产品语言） | 挡住什么 | 代价 / 风险 |
| --- | --- | --- | --- |
| 调低频率上限 | 同一网络每天可提交次数收紧 | 单点高频 | 误伤网吧/公司共用网络的正常用户 |
| 服务端一次性通行证 | 提交前先向平台领一张“限时通行证”，用过即作废 | 重放、脚本预生成 | 需要多一次请求，弱网体验略降 |
| 无感人机验证 | 引入第三方无感验证（如 Cloudflare Turnstile） | 大部分脚本 | 依赖境外服务；大陆可达性需实测 |
| 提交前挑战加难 | 把现有的小题目改成服务端出题、限时 | 低成本脚本 | 低端手机多等几秒 |
| 交互检测 | 检测是否有真实输入轨迹（按键、滚动、停顿） | 纯脚本 | 误判风险；不采集设备信息的前提下能力有限 |
| 内容相似度 | 与近期提交比对，模板化文本相似度高则重点审 | 内容农场 | 只能提示，不能自动拒绝 |
| 评分异常提醒 | 同一公司短时间大量同分/同文本 → 审核台标红 | 组织化刷分 | 需要人工判断 |
| 新对象加严 | 新公司/新项目的头几条评价默认重点审 | 蹭新公司刷分 | 审核变慢 |
| 软处理 | 可疑提交不直接拒绝，进“待定”队列延后展示 | 避免误杀 | 增加审核工作量 |
| 封禁 | 对确认的恶意来源做短期封禁 | 惯犯 | 共用网络会误伤；需谨慎 |

## 5. 组合建议（草案，先记录）

按“先便宜、后复杂”的顺序：

1. **第一步（几乎零成本）**：收紧频率上限 + 把现有挑战改成服务端出题 + 审核台加“同公司短时集中评价”提醒
2. **第二步（需评估）**：引入无感人机验证，重点看大陆网络可用性和误伤率
3. **第三步（按需）**：内容相似度、软处理队列、封禁

> 原则：先用“人工 + 提醒”兜住，不要一上来就上验证码，避免把真实用户挡在门外。

## 6. 待定问题（等要上线时再拍）

1. 是否引入第三方无感人机验证？大陆访问是否稳定？是否与“全链路不经过国内服务”一致？
2. 频率上限调到多少？（现在 5 次/分、100 次/天，是否偏松？）
3. 被判定可疑时：直接拒绝、进待定队列，还是先展示后复核？
4. 是否对“同一公司短时间集中好评/差评”做展示层提示（例如“近期评价异常，仅供参考”）？
5. 封禁的粒度和时长？如何申诉？
6. 是否公开防刷规则的存在（不公开细节）？

## 7. 上线后看什么（观察指标）

- 每天被频率限制拦截的次数
- 人机验证的通过率、平均耗时
- 审核台“相似/集中”提示的命中率与误报率
- 被拒/待定提交里，真实用户申诉的比例
- 单条评价从提交到发布的平均时长（防刷不能把正常流程拖太慢）
